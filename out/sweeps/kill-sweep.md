## Observations from running it

- **Invariant scan P9 is order-sensitive across processes (a defect in `packages/gateway/src/invariants.ts`, or in the audit-event ordering it relies on).** It replays audit events sorted by `_id`. An ObjectId made by the killed process and one made by the restarted process inside the same second do not sort in creation order (the middle bytes are a per-process random value), so a valid chain can replay as `RESERVED -> DISPATCHING` before `INTENT_RESERVED`. It happens when the restart follows the kill within a second, in every failing cell seen, KS2 (kill right after the reserve commit). The auditor says SAFETY: PASS in those cells, every state is allowed, and replayed in event-time order the chain is clean (`p9_replay_clean_in_event_time_order` in the JSON); but by the pass condition they are FAIL cells. Which KS2 cells fail varies from run to run (4 in a first pass at a 60 s limit, 2 in this one, different cells; a re-run of one of them passed), so this sweep is not deterministic at the level of that check.
- **A kill inside a transaction costs the restart about 80 to 90 s** (KS1 `BR_RESERVE_BEFORE_COMMIT` and KS6 `BR_SETTLE_IN_TXN`): the killed process leaves an open MongoDB transaction whose locks the server releases only when it aborts it (`transactionLifetimeLimitSeconds`, default 60 s). With the TEST_PLAN limit of 60 s for `reconcile --until-drained` the five KS6 cells whose reconciler was killed timed out in the first pass (TIMEOUT 5); with 180 s they all passed and drained. The restarted process does recover, only late.
- **`NT_STRIPE_ENABLED=false` does not work** for the runner and reconciler (see the Stripe note above), so the sweep ran with Stripe test mode on for P03's ticket refund.
- **KS4 under REJECT cannot arm.** The simulator applies one fault per request, so `HOLD_RESPONSE_MS` cannot be combined with `REJECT`; the rejection answers before the barrier's 100 ms, the barrier is cancelled, and the three KS4/REJECT cells are NOT_REACHED (TEST_PLAN predicted seven NOT_REACHED cells; these three make ten). In them the run was still audited: FAILED_NO_EFFECT, no duplicate.
